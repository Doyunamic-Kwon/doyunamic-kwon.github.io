노트이 글의 역할

이 글은 앞으로 사용할 논문 리뷰의 작성 가이드입니다. 특정 논문의 결과나 직접 수행한 실험을 보고하는 글이 아닙니다.

먼저, 이 논문이 하는 일을 설명하기

글의 첫 부분에는 논문이 해결하려는 문제와 핵심 방법을 짧게 적습니다. 독자가 본문을 읽기 전에 이 논문을 읽을 이유를 알 수 있도록 설명합니다.

논문 제목, 저자, 발표 정보, 확인한 버전, 논문과 공개 코드의 링크를 함께 남깁니다. Preprint를 읽었다면 발표 여부를 확인한 범위에서 표기합니다.

해결하려는 문제 살펴보기

기존 방법이 어떤 조건에서 어려움을 겪는지 설명합니다. 논문에서 제시한 문제와 작성자가 관심을 가진 문제를 구분합니다.

핵심 방법 따라가기

입력이 들어온 뒤 어떤 처리를 거쳐 출력이 만들어지는지 설명합니다. 필요한 경우 짧은 예시나 직접 그린 그림을 사용하고, 그림을 바탕으로 한 논문의 Figure를 표시합니다.

수식은 방법을 이해하는 데 필요한 것만 포함합니다. 기호는 수식이 처음 등장하는 곳에서 설명합니다.

힌트수식 표시 예시

다음 식은 수식의 표시 상태를 확인하기 위한 예시입니다. 이 식으로 특정 논문의 결과를 주장하지 않습니다.

\[ \operatorname{sim}(q, d) = \frac{q^\top d}{\lVert q\rVert\,\lVert d\rVert} \]

여기서 \(q\)와 \(d\)는 각각 Query와 Document를 나타내는 0이 아닌 Vector입니다. 식은 두 Vector의 방향이 얼마나 비슷한지 계산하는 Cosine Similarity입니다.

결과를 비교 조건과 함께 읽기

주요 결과를 소개할 때에는 Dataset, Baseline, Metric, 비교 조건을 함께 적습니다. 수치가 나온 Table이나 Figure를 표시하고, 해당 결과가 뒷받침하는 범위에서 해석합니다.

확인할 항목 기록할 내용
평가 대상 어떤 Task와 Dataset을 사용했는가
비교 방법 어떤 Baseline과 비교했는가
평가 기준 어떤 Metric을 사용했고 값의 방향은 무엇을 뜻하는가
비교 조건 모델, 데이터, 계산 비용 등의 조건이 어떻게 다른가
결과의 위치 논문의 어느 Table 또는 Figure에 제시됐는가

한계와 해석 구분하기

저자가 밝힌 한계와 제 해석을 각각 적습니다. 논문에서 확인하지 않은 설정으로 결론을 넓히지 않고, 추가 확인이 필요한 부분은 질문으로 남깁니다.

구현 관점의 메모 남기기

공개 코드를 읽었다면 확인한 파일이나 함수의 링크를 남깁니다. 직접 작성하거나 실행한 내용이 있다면 수행한 범위와 결과를 구체적으로 적습니다.

다음 코드는 코드 블록의 표시 상태를 확인하기 위한 예시입니다. 사이트를 만들거나 글을 게시할 때 자동으로 실행되지 않습니다.

def format_paper_title(title: str, year: int) -> str:
    return f"{title} ({year})"

출처와 수정 기록 남기기

논문과 코드의 원래 링크를 유지하고, 내용이 바뀌면 수정일을 갱신합니다. Quarto의 참고문헌 기능으로 본문 인용과 참고문헌 목록을 연결할 수 있습니다.

인용 형식 예시로 RAG 논문 (Lewis 기타 2020년)을 표시했습니다. 이 인용은 참고문헌 표시를 확인하기 위한 것이며, 위 가이드의 예시 수식이나 코드를 이 논문에서 가져왔다는 뜻은 아닙니다.

참고문헌
